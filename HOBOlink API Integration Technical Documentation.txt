HOBOlink API Integration Technical Documentation
1. HOBOlink API Overview
The HOBOlink API allows programmatic access to data from Onset HOBO data loggers. Unlike the CORIS API, HOBOlink uses OAuth2 authentication and has a different data structure. The API provides endpoints for fetching historical environmental sensor data from specific loggers over defined time periods.
2. Authentication Process
OAuth2 Client Credentials Flow
HOBOlink uses the OAuth2 client credentials flow, which requires:


* client_id: Identifies your application to HOBOlink
* client_secret: Proves your application's identity
* User ID: Required for data access


Authentication steps:


1. Make a POST request to https://webservice.hobolink.com/ws/auth/token
2. Include credentials in the request body as form data
3. Receive an access token valid for a limited time period
4. Use this token for subsequent data requests
Code Implementation
def get_hobolink_token(self) -> str:


    # Check if cached token is still valid


    current_utc = self.get_current_utc()


    if ('HOBOLINK' in self.api_tokens and 


        'HOBOLINK' in self.token_expiry and 


        current_utc < self.token_expiry['HOBOLINK']):


        return self.api_tokens['HOBOLINK']


    # Request a new token


    token_url = 'https://webservice.hobolink.com/ws/auth/token'


    headers = {


        'Content-Type': 'application/x-www-form-urlencoded',


        'Accept': 'application/json'


    }


    data = {


        'grant_type': 'client_credentials',


        'client_id': self.apikeys['HOBOLINK']['client_id'],


        'client_secret': self.apikeys['HOBOLINK']['client_secret']


    }


    # Make the token request


    response = requests.post(token_url, headers=headers, data=data)


    


    # Parse and store the token


    token_data = response.json()


    self.api_tokens['HOBOLINK'] = token_data['access_token']


    self.token_expiry['HOBOLINK'] = current_utc + token_data['expires_in'] - 60


    


    return self.api_tokens['HOBOLINK']
3. Data Retrieval Process
Historical Data Endpoint
To retrieve historical data, use the /ws/data/file/JSON/user/{user_id} endpoint:


* Method: GET
* Base URL: https://webservice.hobolink.com/ws/data/file/JSON/user/{user_id}
* Authorization: Bearer token in the header
* Parameters:
   * loggers: Logger serial number (e.g., "20284065")
   * start_date_time: Start date in 'YYYY-MM-DD HH:MM:SS' format
   * end_date_time: End date in 'YYYY-MM-DD HH:MM:SS' format

Key Fields Explained
* logger_sn: Serial number of the data logger device
* sensor_sn: Individual sensor identifier, typically {logger_sn}-{sensor_index}
* timestamp: Time of the reading in ISO format with 'Z' indicating UTC
* si_value: Measurement in SI units (e.g., Celsius for temperature)
* si_unit: SI unit of measurement (e.g., "°C" or "%")
* us_value: Measurement in US units (e.g., Fahrenheit for temperature)
* us_unit: US unit of measurement (e.g., "°F" or "%")
* sensor_measurement_type: Type of measurement (e.g., "Temperature" or "RH" for relative humidity)
Important Data Characteristics
1. Each observation represents a single reading from a specific sensor at a specific time
2. A logger typically has multiple sensors (e.g., temperature and humidity)
3. Timestamps are in UTC, marked with 'Z' suffix
4. Temperature is provided in both Celsius (SI) and Fahrenheit (US)
5. Humidity (RH) uses the same value for both SI and US
6. The API may include other measurement types like "Battery" or "Dew Point" that may need filtering
5. Data Processing and Transformation
To integrate HOBOlink data with the existing system, we need significant transformation:
Transformation Steps
1. Parse timestamps: Convert ISO timestamps to Unix timestamps (seconds since epoch)
2. Organize by sensor and reading type: Group readings by sensor ID and measurement type
3. Map to standard format: Convert to the standard schema that matches CORIS data format
4. Type conversion: Cast values to appropriate types (Float32 is critical to prevent type mismatches)
5. Add metadata: Add source identifiers and naming conventions
Data Extraction Example
readings_by_sensor = {}


for obs in observations:


    # Convert timestamp to UTC


    timestamp_str = obs['timestamp'].rstrip('Z')


    timestamp = datetime.datetime.strptime(timestamp_str, '%Y-%m-%d %H:%M:%S')


    timestamp = timestamp.replace(tzinfo=datetime.timezone.utc)


    timestamp_utc = int(timestamp.timestamp())


    # Determine reading type and value


    sensor_id = f"{logger_id}_{obs['sensor_sn']}"


    measurement_type = obs['sensor_measurement_type'].lower()


    


    if 'temperature' in measurement_type:


        reading_type = 'SensorReadingF'


        reading_value = float(obs['us_value'])  # Use Fahrenheit


    elif 'rh' in measurement_type:


        reading_type = 'SensorReadingRh'


        reading_value = float(obs['si_value'])


    else:


        continue  # Skip other sensor types


        


    # Organize readings by sensor and reading type


    key = (sensor_id, reading_type)


    if key not in readings_by_sensor:


        readings_by_sensor[key] = {


            'SensorID': [],


            'SensorReadingUTC': [],


            reading_type: [],


            'QueryUTC': [],


            'DeviceName': [],


            'SensorName': [],


            'SensorType': []


        }


        


    # Add data points


    readings_by_sensor[key]['SensorID'].append(sensor_id)


    readings_by_sensor[key]['SensorReadingUTC'].append(timestamp_utc)


    readings_by_sensor[key][reading_type].append(reading_value)

6. Data Type Considerations
A critical issue is the default data type used by HOBOlink API responses. The numeric values from the API are parsed as Float64 by default, but the existing system expects Float32:


# Create DataFrame from readings


df = polars.DataFrame(readings)


# IMPORTANT: Cast float values to Float32 to prevent type mismatch


if reading_type in df.columns:


    df = df.with_columns(polars.col(reading_type).cast(polars.Float32))


Failure to perform this casting will result in errors like:


Error writing combined readings to database: type Float64 is incompatible with expected type Float32

	8. Implementation Requirements
To successfully integrate HOBOlink data:


1. Environment variables required:


   * HOBOLINK_CLIENT_ID: OAuth client ID
   * HOBOLINK_CLIENT_SECRET: OAuth client secret
   * HOBOLINK_USER_ID: User ID number
   * HOBOLINK_LOGGERS: Comma-separated list of logger serial numbers


2. Class initialization parameters:


   * Set api_sources to include 'HOBOLINK'
   * Provide HOBOlinkUserID and HOBOlinkLoggers


3. Data type handling:


   * Ensure explicit casting of float values to Float32
   * Apply casting at all data processing stages


4. ID mapping:


   * Add HOBOlink-specific identifiers
   * Include empty placeholders for CORIS IDs for compatibility

Summary
The HOBOlink API integration provides a second data source that complements the CORIS API. By following the authentication, data retrieval, and processing steps outlined above, you can successfully retrieve environmental sensor data from HOBOlink loggers. The key challenges include OAuth2 authentication, timestamp parsing, data type conversion, and aligning the HOBOlink data structure with the existing CORIS-based system.
